# 美食验证工作流

> 来自 2026-06-15 新疆伊犁攻略会话

## 场景

用户分享网友/抖音/小红书推荐的餐厅，要求加入旅行攻略。直接加入可能收录不存在的店铺。

## 标准流程

1. **记录到plan，不入HTML** — 所有推荐先记到独立文件，标注来源和状态
2. **逐家 web_search 验证** — 搜"店名+城市"，确认百度/高德/携程/大众点评/抖音有收录
3. **小地方路边店** — 独库服务区、精河/乔尔玛等无线上痕迹的店，留在plan不入HTML
4. **加入HTML** — 用搜索到的精确地址，非用户口述的模糊地址
5. **修正偏差** — 搜到的店名与用户提供的不一致时，以搜索结果为准
6. **🔑 高德 POI 精确链接** — 用户在高德App中搜到店铺后，复制分享链接获取 POI ID，替换泛搜索链接为 `https://www.amap.com/ssr/place/{POI_ID}`

## 高德 POI 链接格式

- 泛搜索（备选）：`https://www.amap.com/ssr/search?keyword=xxx`
- 精确定位（推荐）：`https://www.amap.com/ssr/place/{POI_ID}`
- 用户从高德App分享的链接含 `source=sug` 参数，只取 `/ssr/place/{POI_ID}` 部分
- **注意：** 高德 SSR 页面 JS 渲染，`web_extract` 始终失败（36+ 次验证）。不要对高德链接使用 web_extract

## 验证标准

- ✅ 两个以上来源收录 → 真实，入HTML
- ⚠️ 一个来源或名字偏差 → 修正后加入
- ❌ 完全搜不到 → 标注"未验证"，不入HTML

## HTML 编辑铁律

- **改前必备份**：`cp file file.bak.$(date +%m%d%H%M)`
- **execute_code 内用 `open()` 读写**，禁用 `read_file()`——后者返回行号前缀会污染文件
- **所有修改在一次 execute_code 完成**，避免多次调用互踩
- **改后 grep 验证**：关键内容存在 + 文件末尾完整

## 实战数据

78家餐厅验证：72真实 / 4搜不到 / 2名字偏差 → 真实率92.3%
最终精简至70家（含42个精确POI链接）
